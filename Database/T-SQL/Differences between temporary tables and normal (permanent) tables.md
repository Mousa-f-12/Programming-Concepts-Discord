# الفرق بين Temporary Tables و Permanent Tables

## 1. Lifespan and Scope — دورة الحياة والنطاق
* **Temporary Tables:** جداول مؤقتة تعيش لفترة محدودة، وتنتهي حسب نوعها ونطاقها، مثل انتهاء الاتصال.
* **Permanent Tables:** جداول دائمة تبقى موجودة حتى يتم حذفها يدوياً، ولا ترتبط بدورة حياة الاتصال.

## 2. Performance and Storage — الأداء والتخزين
* **Temporary Tables:** تُخزّن في قاعدة البيانات `tempdb`، وتُستخدم عادةً لتخزين البيانات المؤقتة والنتائج الوسيطة.
* **Permanent Tables:** تُخزّن داخل قاعدة البيانات الأساسية، وتُستخدم لحفظ بيانات النظام بشكل دائم.

## 3. Usage — الاستخدام
* **Temporary Tables:** نستخدمها عندما نحتاج إلى تخزين بيانات مؤقتة أثناء تنفيذ عملية معينة، مثل نتائج استعلام نحتاج إلى معالجتها لاحقاً.
* **Permanent Tables:** نستخدمها لتخزين بيانات التطبيق الأساسية، مثل العملاء والموظفين والطلبات.

## 4. Transaction Logging — سجلات المعاملات
* **Temporary Tables:** تشارك في المعاملات (`Transactions`)، ويمكن التراجع عن التعديلات عليها باستخدام `ROLLBACK`.
* **Permanent Tables:** تشارك أيضاً في المعاملات، وتُسجّل عمليات التعديل عليها لضمان سلامة البيانات.

## 5. Backup and Recovery — النسخ الاحتياطي والاستعادة
* **Temporary Tables:** لا تدخل ضمن النسخ الاحتياطي الاعتيادي لقواعد بيانات المستخدم، وتُفقد عند إعادة تشغيل SQL Server.
* **Permanent Tables:** تدخل ضمن النسخ الاحتياطي، ويمكن استعادة بياناتها عند حدوث مشكلة.

---

## الخلاصة

| المقارنة | Temporary Table | Permanent Table |
| :--- | :--- | :--- |
| **التخزين** | `tempdb` | قاعدة البيانات الأساسية |
| **دورة الحياة** | مؤقتة | دائمة |
| **الاستخدام** | بيانات وسيطة | بيانات التطبيق |
| **ROLLBACK** | مدعوم | مدعوم |
| **Backup** | لا تدخل في النسخ الاعتيادي | تدخل في النسخ الاحتياطي |

> **مثال واقعي لتثبيت الفكرة:**
> تخيّل نظام بنك:
> * جدول `Customers`: جدول دائم يحتفظ ببيانات العملاء.
> * جدول `#CustomersWithLoans`: جدول مؤقت نستخدمه لاستخراج العملاء الذين لديهم قروض ومعالجة بياناتهم، ثم ينتهي دوره.

**الفكرة الأساسية:** الجدول الدائم يحفظ بيانات النظام، أما الجدول المؤقت فيساعدنا على معالجة البيانات دون الحاجة إلى الاحتفاظ بها بشكل دائم
